## 需求清单

### #248 Suspend to disk instead of RAM
- 场景：提交者在 README 中看到关于 CRIU 的说明，想知道是否能将应用状态写入磁盘以便重启或释放 RAM 后再恢复。citeturn2view0
- 需求：提供一个挂起到磁盘的可选路径（基于 CRIU 或等效方案），让用户在关机/重启后继续此前的游戏或工作场景。citeturn2view0
- 讨论：Merrit 回应自己有可行思路但需要时间实现，目前仅打算面向 Linux，并提到 Wayland 的 checkpoint/restore 可能是关键，也认为 Windows/macOS 需要各自开发。citeturn3view0

### #247 [Feature Request] Use controller combo to freeze/unfreeze apps
- 场景：Windows 用户希望在手柄操作时，直接用某个按钮组合来冻结或恢复应用而不必切换到键盘。citeturn14view0
- 需求：增加对控制器组合按键的映射选项，将其绑定为 Nyrna 的 freeze/unsuspend 动作，使手柄玩家也能便捷控制挂起。citeturn14view0
- 讨论：有用户提到可以通过 ReWASD、Joy2Key、Xpadder 等外部映射继续操作，但部分游戏会以为是作弊；Merrit 也提醒 Windows 可能同样触发检测，Linux 上则用 Input Remapper 做替代。citeturn15view0

### #243 Windows Tray Icon Disappears
- 场景：在 Windows Explorer 崩溃或从睡眠唤醒后，Nyrna 的托盘图标消失但进程仍在，用户无法唤出 GUI，只能终止进程再启动。citeturn19view0
- 需求：确保托盘图标在 Explorer 重启、睡眠切换等情况下仍旧可见或提供替代入口，让用户不必强制关闭并重启 Nyrna。citeturn19view0
- 讨论：作者联想到 cppcryptfs 那种托盘恢复机制，询问是否需要在 Explorer 重启后重新创建图标。citeturn20view0

### #242 Auto suspend when sleeping / auto resume on wake
- 场景：视频中展示按下电源键睡眠会自动暂停 Elden Ring，唤醒后又自动恢复，提问是否已有类似自动行为。citeturn23view0
- 需求：为系统睡眠/唤醒链路绑定自动挂起与恢复逻辑（可作为开关），让游戏在睡眠后继续上一次进度。citeturn23view0
- 讨论：Merrit 询问当前是否是通过脚本调用 `nyrna --toggle`，提问者希望内建自动挂起/恢复，后续确认功能只打算支持 Linux。citeturn24view0

### #241 [Feature] Also toggle inactivity blocking
- 场景：Steam/Lutris/Gamescope/gamemode 等在游戏运行时会阻止屏幕锁定，但一旦游戏被暂停，这些阻止行为就失效，容易触发锁屏。citeturn27view0
- 需求：在挂起/恢复流程中同步管理“阻止屏幕锁定”的状态或提供开关，确保即便暂停后也能维持所需的防锁定行为。citeturn27view0
- 讨论：该 issue 暂无额外评论，仍以原始描述为主。citeturn27view0

### #239 [Feature request] Command-Line Support
- 场景：已有用户用 AHK 脚本在 Left 4 Dead 2 与 Brave 之间切换，希望 Nyrna 也能被脚本控制。citeturn30view0
- 需求：提供 CLI 接口（例如 `nyrna.exe Suspend "app.exe"` / `nyrna.exe Unsuspend "app.exe"`），方便外部脚本按需挂起或恢复进程。citeturn30view0
- 讨论：Merrit 表示会进一步思考如何扩展命令行接口。citeturn31view0

### #238 [Feature Request] Set system time to suspend time before resume
- 场景：某些对时间敏感的游戏在恢复后会把剧情快进，补救方法是把系统时间调回挂起时刻。citeturn34view0
- 需求：提供一个可选的机制，在恢复前将系统时钟回拨到挂起的时间戳，从而避免字幕/剧情处理“向前跳秒”的情况（需注明可能影响其他软件）。citeturn34view0
- 讨论：Merrit 认为直接修改系统时间风险较高，建议通过 Linux 上的 libfaketime 跟随挂起/恢复运行脚本来伪造时间。citeturn35view0

### #237 [Feature Request] Separate pause and resume hotkey
- 场景：用单一 toggle 热键控制暂停/恢复会导致外部状态跟踪失准，无法明确知道当前状态。citeturn38view0
- 需求：允许为暂停和恢复分别指定热键（非切换型），确保状态管理可由用户精确掌控且外部逻辑容易读取。citeturn38view0
- 讨论：Merrit 感谢建议并会继续考虑，此后又有用户在该 issue 下补充同类需求。citeturn39view0

### #233 [Feature Request] Allow hiding applications from window list
- 场景：有几个永远不想挂起的常用程序也会出现在窗口列表里，影响体验；在直播/流媒体场景下希望自动根据流状态控制挂起。citeturn42view0
- 需求：提供例外/排除列表（或永久隐藏某些进程）的设置，让指定应用不出现在 UI 列表，同时便于与流媒体自动化配合。citeturn42view0
- 讨论：Merrit 觉得这是个好主意，其他用户也分享了流媒体/直播场景以及 fork 版的实现思路。citeturn43view0

### #232 [Feature Request] Support for Game Controller Input and Switching Shortcuts
- 场景：希望更好地结合 Moonlight Stream 等流媒体服务，用游戏手柄操作窗口选择与切换。citeturn46view0
- 需求：检测游戏手柄并允许用 D-pad/摇杆导航、按键选择或切换窗口，提供控制提示并支持自定义快捷键（示例：Ctrl+手柄按钮切换）。citeturn46view0
- 讨论：Merrit 觉得想法有趣，社区还提出结合 Xbox Game Bar、小工具或命名管道守护进程等更深层次的方案。citeturn47view0

### #231 [Feature Request] show application icons in window tiles
- 场景：当前窗口列表只有标题，选项识别依赖文字，用户希望像任务管理器那样显示图标提高速度。citeturn50view0
- 需求：在窗口瓦片/列表中展示进程图标，结合标题一起呈现，帮助快速识别目标程序。citeturn50view0
- 讨论：Merrit 也表示会找时间研究如何在列表中显示图标。citeturn51view0

### #224 [Feature request] Auto-resume at timed interval, or window focus/click
- 场景：希望像控制台那样，能让暂停的应用定期恢复（检查邮件）或者点击窗口/将其聚焦时自动唤醒，从而提升日常使用与电池体验。citeturn54view0
- 需求：① 支持按指定时间间隔自动 unsuspend 并在设定时长后重新挂起应用；② 当用户点击或聚焦某个挂起窗口时自动恢复（可借鉴 xdotool/xprop 的焦点检测方法）。citeturn54view0
- 讨论：Merrit 认为两项功能都增加复杂度，特别是点击/聚焦后恢复在 Wayland 上当前不可行，需进一步评估。citeturn55view0
